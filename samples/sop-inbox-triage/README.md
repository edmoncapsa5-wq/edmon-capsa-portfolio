# SOP Sample — Shared Inbox Triage

## Purpose
Keep a shared operations inbox organized while ensuring material requests reach the correct owner without unsupported decisions.

## Scope
Applies to routine incoming operational email. It does not authorize legal, HR, financial, security, or policy decisions.

## Procedure
### 1. Identify the message
Capture sender, subject, received time, requested action, deadline, and any referenced account/project.

### 2. Classify the request
Use one of these operational states:
- **Routine / actionable** — authorized and sufficiently clear.
- **Needs information** — missing evidence prevents completion.
- **Needs decision** — requires client/manager judgment or authority.
- **High consequence** — financial, legal, privacy, security, HR, or irreversible impact.
- **Informational** — no action required.

### 3. Take the lowest-risk authorized action
- Complete routine reversible actions when authority is clear.
- Draft or prepare work when execution requires approval.
- Do not infer policy from previous examples when the current case is materially different.

### 4. Escalate only what needs escalation
A useful escalation contains:
1. **Status** — what is known.
2. **Impact** — what is blocked or at risk.
3. **Recommended action** — the safest supported path.
4. **Next state** — what will happen after the decision.

### 5. Record completion
Update the task or communication log with the action taken, owner, date, and any unresolved dependency.

## Quality checks
Before closing an item:
- Was the correct request identified?
- Was the action within authority?
- Was material ambiguity surfaced rather than guessed?
- Is the next responsible party clear?
- Can another operator understand the current state without reconstructing the email thread?

## Example escalation
> Status: The requested customer update is prepared, but the account contains two conflicting billing addresses. Impact: Updating the wrong address could affect future billing documents. Recommended action: Confirm which address is authoritative before changing the record. Next state: Once confirmed, the CRM update can be completed immediately.
