# MarginLatch — Scope-control workflow demonstration

**Status: Working prototype and proposed customized service. This example is fictional; it is not a paying-client case study.**

## The problem
A studio agrees to build five website pages with two revision rounds. Later, a client asks for a sixth page with a custom form. Is that an included correction or an additional deliverable? What should happen before the work starts?

MarginLatch helps the studio document a **request → estimate → client decision → delivery → billing** workflow without adopting another subscription.

## Fictional change-request example

| Item | Example |
|---|---|
| Initial scope | Five pages; two design revision rounds |
| New request | Sixth landing page and custom form |
| Classification | Added work outside agreed scope |
| Additional effort | Four hours |
| Illustrative rate | $75/hour |
| Proposed additional fee | **$300** |
| Status | **Quoted; not approved** |
| Next action | Request explicit client approval before proceeding |

**Example client message:**

> Happy to add the extra landing page and form. Those items are outside our agreed five-page scope. The additional work is estimated at $300 and may move the delivery date by two working days. Would you like us to approve this as a separately priced addition, or keep the original scope and timeline?

This example does not grant permission to invoice or start work without genuine approval. Client contracts control the actual process.

## Fictional video-production change request

A production studio agrees to deliver one 60-second campaign film with two consolidated revision rounds. Following the second round, the client requests two additional 15-second cutdowns with separate social-media framing.

| Decision field | Example |
|---|---|
| Original scope | One 60-second master; two revision rounds |
| Client request | Two new 15-second versions, each reformatted for social |
| Type | Added deliverables, not an ordinary correction |
| Extra editing / QA effort | 3.5 hours, illustrative |
| Proposed rate | $85/hour, illustrative |
| Quote | **$297.50** |
| Client approval status | **Pending — do not start** |
| Recorded impact | One additional business day after approval, illustrative |

**Example approval email:** “Happy to provide two 15-second cutdowns. These are new outputs beyond the agreed 60-second master, so the additional estimate is $297.50 and one business day after approval. Please reply with approval of the added fee and delivery date before we schedule the work.”

**Boundary:** A timestamped-feedback platform (such as Frame.io) is useful for editorial notes. MarginLatch does not connect to it or provide integrated billing or legally verified e-signatures. It records the separate internal quote/decision trail using editable files.

## Two-minute fit check

The goal is not to add another tracker where one already works. Before quoting a setup, answer these three questions:

1. When a client requests another page, revision round, or cutdown, **where is the original scope checked**?
2. Who records the **extra price, timing impact, and client's actual approval** before that work begins?
3. At the end of each project, who verifies that **approved additions were invoiced**, rather than simply completed?

If each answer has an owner and an accessible existing record, you probably do not need MarginLatch. If there is a gap, a narrow, customized approval trail may help.
